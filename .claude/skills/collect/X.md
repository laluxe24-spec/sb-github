# X

Xのアカウントには2種類ある。

| 種類 | 対象 | やること |
|---|---|---|
| 投稿型 | 7アカウント | 投稿の本文を全部そのまま集める |
| スクショ型 | @kw1ew | 会話スクショを集めて、使えるものだけ1枚ずつ選んで残す |

## 共通: 準備とログイン

- プログラムは`01_Sources/02_X/scripts/`にある(投稿型もスクショ型も共通)
- 初回や`node_modules`が消えている時は、先に`npm install && npx playwright install chromium`
- ログインが切れていたら`node login.js`を実行し、りゅーじ君本人がその場でXにログインする(ブラウザが開き、ログインを検知すると`auth.json`に保存して自動で閉じる)

## 投稿型
対象アカウントの投稿を`posts.json`に保存する。画面の文字ではなく、Xが裏で受け取っている元データから取るので、「さらに表示」で折りたたまれた長文も全文入る。反応の数字も一緒に保存する。確認を取らずに進めてよい。

- 残すもの: 本人の投稿と、本人のスレッドの続き(自分への返信)
- 外すもの: 他の人への返信、リポスト
- 1件の中身: `id`・`url`・`text`(全文)・`created_at`・`is_long`(折りたたまれる長文か)・`parent_id`(スレッドの続きなら親の投稿ID)・`metrics`(views=表示回数・likes・reposts・replies・bookmarks・quotes)・`metrics_at`(数字を取った日時)
- 保存済みの投稿にもう一度当たった時は、本文がより長く取れたら上書きし、数字は最新にする

### フォルダ
```
01_Sources/02_X/
├── scripts/                 収集プログラム(スクショ型と共通)
├── data/@<アカウント名>/posts.json   いつも追っている人
└── 候補/<プロジェクト>/@<アカウント名>/  リサーチのために仮で集めた人
```

### 手順

```bash
cd 01_Sources/02_X/scripts
node collect_posts.js <アカウント名> [何ヶ月前まで] [--full]
```

- アカウント名は`@`なしで渡す(例: `mai_x0x0_21`)
- **新しいアカウントを追加する**: `node collect_posts.js <アカウント名>`(何ヶ月を省略すると24ヶ月分)
- **新着だけ取る**: `node collect_posts.js <アカウント名> 1`(保存済みの投稿に追いついたら止まるので、数秒〜数十秒で終わる)
- **本文の取り直し・数字の更新**: `node collect_posts.js <アカウント名> 1 --full`(保存済みにぶつかっても止まらず、指定した月数まで全部見直す。リサーチの前に使う)
- **全員の新着をまとめて取る**: `node auto_check.js`(`@kw1ew`以外の全員に「新着だけ取る」を順番に実行)
- 何人も続けて取る時は、1人ごとに20秒ほど休む(Xに制限されないように)
- 最後に「投稿のデータを1つも受け取れなかった」と出たら、Xが裏のデータの名前を変えた可能性がある。一緒に出る名前の一覧を見て、プログラムの名前の条件を直す

## スクショ型(@kw1ew)
X上の会話スクリーンショットを取得し、「口説き・ラポール構築のテクニック例」として使えるものだけを1枚ずつ判断して`01_Sources/02_X/data/@kw1ew/スクショ/`に保存する。**厳選が核心**。確認を取らずに最後まで進めてよい。

### 手順

1. **新着取得**:
   ```bash
   cd 01_Sources/02_X/scripts
   node collect_media.js 30
   ```
   - 引数は**件数だけ**。アカウント名は渡さない(`kw1ew`はプログラム内で固定。アカウント名を渡すと件数がNaNになり0件で終わる)
   - 取得済みの画像は`processed_ids.json`で自動的に飛ばされる。新着0件ならここで終了
   - バックグラウンド実行にしない(完了を待たずに終わってしまい、厳選まで進まない)
   - 画像は`scripts/screenshots_batchN/`に保存される
2. **厳選**: `screenshots_batchN/`の画像を1枚ずつ見て、下の基準で判定する
3. **保存**: 残す画像を`data/@kw1ew/スクショ/`へ、今ある最大の番号の続きから連番で(例: 167.jpg)コピーし、`data/@kw1ew/manifest.json`に`{"file": "スクショ/167.jpg", "tweet_url": "..."}`を追記する
4. **片付け**: `scripts/screenshots_batchN/`を削除する
5. **記録**: `/Users/ryuji/sb-mac-logs/kw1ew-collector.log`に、取得数・採用数・除外数・採用ファイル名を書く。判断に迷った画像があれば一言メモを残す

### 残す/除外の基準

**残す**: 本人と相手の2人の実際のトーク画面(マッチングアプリ)で、口説き・ラポール構築のテクニックが分かるもの。名前を聞く、褒める、語呂合わせ・こじつけ、キャラ設定のジョークなどを使ったオープニング〜関係づくりのやり取り。

**除外**:
- 解説用の注釈(吹き出し・矢印)がかぶせてある画像。同じ会話の無注釈版があれば、そっちだけ残す
- スマホを手に持って撮った写真(スクショではない)
- 本の表紙・ニュース・食事・商品紹介など、トーク画面と関係ない画像
- 性的な体験報告・性的な内容・際どい画像
- 受講生やお客さんの感想・お礼・相談メッセージ
- LINE画面(相手アイコンが実写真でも、花・惑星などの汎用アイコンでも除外)
- 出どころが分からない断片的なやり取り
- ダウンロードに失敗した空・壊れたファイル

迷ったら「実際の口説き会話のテクニック例になっているか」で判断し、際どいものは除外する。採用率は普段10〜20%くらい。
