# 発信するものを作る

りゅーじ君は書き方のプロじゃない前提で、プロとして作って提案する。

## 1. 始める前に読む

- そのプロジェクトのルール(`04_Projects/<プロジェクト>/`): ゴール・立ち位置・話し方(口調)・構造・媒体ごとの決まり
- 最近の`下書き.md`と`投稿記録.md`: 同じテーマ・同じ型が続かないように
- そのプロジェクトの内容の正解(恋愛なら`02_Knowledge/01_ネタ/恋愛/モテと非モテの基準.md`): 何が良くて何がダメか。投稿の中身はこれと矛盾させない
- `02_Knowledge/03_成功と失敗/<プロジェクト>.md`: 同じ失敗をしない

## 2. ネタを選ぶ

- `02_Knowledge/01_ネタ/`から「使用: 未」を選ぶ。「なぜ伸びたか」が書いてあるものを優先
- 書き方の参考は`02_Knowledge/02_分析/`(どのファイルかはプロジェクトのルールに書いてある)

## 3. 書く

- 口調はプロジェクトのルールの「話し方」に合わせる。まだ決まっていなければ、ルールに書いてあるお手本(りゅーじ君が高い点をつけた投稿)に合わせ、報告で「口調が未決定」と伝える
- 媒体ごとのやり方は下の表のファイルを読む
- 案は1つに絞らず、切り口を変えて2〜3個出す

| 媒体 | 読むファイル |
|---|---|
| X | `X.md` |

新しい媒体(note・Threadsなど)で作る時は、同じ形で`<媒体名>.md`をこのフォルダに作ってから始める。

## 4. 出す前に自分で見る

- 誰かの投稿を丸ごと一語一句写していないか(よく使われるセリフや言葉が同じなのはOK)・誇張・言い切りの一般化
- 中身が、そのプロジェクトの内容の正解(恋愛なら「モテと非モテの基準」)と矛盾していないか
- りゅーじ君の体験談が混ざっていないか

## 5. 報告の形(秘書AIへ)

- 本文(返信欄まで全文)
- 使ったネタ・分析(ファイル名と項目)
- 選んだ切り口と理由
- 自分で気になっている弱いところ
- 「こうしたらもっと良くなる」の提案

## 6. 終わったら

- 使ったネタの「使用」に日付を書く
- りゅーじ君がOKしたものは`下書き.md`の一番上へ
- **りゅーじ君が直したら、毎回その場で記録する**(秘書AIが書く)。`下書き.md`のその投稿の下に、次の形で残す。投稿したら記録ごと`投稿記録.md`に移す

```
### 直した記録(M/D)
- 元の案:
- 直した文:
- どこを直したか: (1行目・言い回し・構成・長さなど)
- なぜ: (りゅーじ君の言葉をそのまま。言っていない理由を想像で足さない)
```
