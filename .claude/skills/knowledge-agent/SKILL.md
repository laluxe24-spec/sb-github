# ナレッジ化(収集データ→Knowledge)

02_Sourcesに集まった生データを分析し、りゅーじ君が実際に使える形に整えて03_Knowledgeへ保存するスキル。手順・判断基準は無人実行と完全に同じものを、`07_System/launchd/knowledge_agent_prompt.md`に1本化して管理している。

**必ず`07_System/launchd/knowledge_agent_prompt.md`を読み、そこに書かれている手順(新着の洗い出し→情報源の種別判定→内容分析→除外基準・根拠レベルの適用→内部管理・完了処理)にそのまま従う。**このSKILL.mdでは内容を複製しない(手順が更新された時に二重管理でズレるのを防ぐため)。

## 分析の考え方(このスキルが目指す形)

このスキルの目的は「情報を貯めること」ではなく、**りゅーじ君自身の成長のために、「こういう場面になったらこう考える」「こういう時はこう行動する」という、場面(条件)とセットになった判断・行動の型を作ること**。単なる要約・感想止まりにせず、必ず「どんな状況で」「何を考え/どう動けば」使えるのかという発動条件を添える。この考え方は`knowledge_agent_prompt.md`の全体(最重要ルール・2章の行動系/会話系/要約系すべて)に貫かれている大方針なので、個別の分析をする時に見失わないこと。

## 手動実行時の違い

- 手動で頼まれた時は「無人実行モード」の自己紹介文言(プロンプト冒頭の説明)は不要。秘書エージェント自身が今その場で同じ分析ロジックを使って処理している、という扱いでよい。
- プロンプト内の「Bashツールは使えない設定」という注意書きは、無人実行環境固有の制限。対話セッションでは通常通りBashツールを使ってよい(ただしこの処理自体はRead/Write/Edit/Glob/Grep/Agentだけで完結する内容なので、普段Bashを多用する必要はない)。
- 「今すぐ〇〇だけナレッジ化して」のように対象が指定された場合は、`0. 新着の洗い出し`の対象を指定されたものだけに絞ってよい(それ以外は無人実行の巡回に任せる)。
- 処理が終わったら、`knowledge_progress.json`・`knowledge_meta.json`・`07_System/更新履歴.md`への記録は無人実行時と同様に行う(手動実行だからといって省略しない、次回以降の無人実行と記録を共有するため)。
