# 副業のナレッジ

りゅーじ君の副業(恋愛X・note販売・ポケカ・動画AIなど)を成功させるための知見の宝庫。1つの副業で分かったことを、他の副業でも使えるように、副業ごとに分けずに1か所に貯める。

りゅーじ君個人の成長のためのもの(考え方・恋愛・生活)は、ここではなく`03_MyKnowledge`(my-knowledgeスキル)。

## 何をどこに入れるか

| 種類 | 何を | どこから来る | 保存先 |
|---|---|---|---|
| ネタ | 発信に使えるネタ | 集めた生データ(`01_Sources`) | `02_Knowledge/01_ネタ/<ジャンル>/` |
| 分析 | 調べて分かったこと(伸びる型・競合・売れ筋・市場) | research-aiの報告 | `02_Knowledge/02_分析/` |
| 成功と失敗 | やってみて分かったこと | 投稿記録の振り返り、副業での出来事 | `02_Knowledge/03_成功と失敗/` |
| ノウハウ | 外から学んだ使える技術(書き方・売り方など) | 集めた生データ(`01_Sources`) | `02_Knowledge/04_ノウハウ/` |

**全部のエントリに「どの副業で分かったことか」を書く**(例: `副業: 恋愛X`)。

**`ルール.md`との関係**: `04_Projects/<副業>/ルール.md`は「今の決まり」(結論だけ)。ルールが変わった時は、その理由・元になった分析や失敗をここに残す。

## 1. ネタ

### 新着の洗い出し

`02_Knowledge/_管理/progress.json`の`processed_files`に無いものだけを対象にする。新着が無ければ何もしない。対象を指定された時(「〇〇だけ」)は、それだけに絞ってよい。

対象ソース:
- `01_Sources/02_X/data/@<各アカウント>/posts.json`(投稿。`id`で処理済み判定)
- `01_Sources/02_X/data/@kw1ew/スクショ/*.jpg`(会話スクショ、画像のまま読む。OCR不要)
- `01_Sources/03_TikTok/data/*/transcripts/*.md`(TikTokの文字起こし)
- `01_Sources/04_YouTube/data/*/transcripts/*.md`(YouTubeの文字起こし)
- `01_Sources/01_Kindle/data/*/本文.md`(本、`kindle/<本のタイトル>`の形でprocessed_files照合)

**除外基準(問答無用で対象外)**: 煽情的・操作的なテンプレ投稿(釣り文句集、「女性を洗脳する」系の商材宣伝、性的体験の実況)、怪しい商材の宣伝、MBTI・血液型などの根拠のない分類。信頼している発信者(乾さん・はやとさん)の内容でも、この基準に該当するもの(自著宣伝・講師紹介など技術的内容がないものを含む)は除外する。

除外しなかったものは、読者が「あるある」「知らなかった」と思えて、投稿のテーマ・切り口・セリフになるかを見る。ならないものは保存しない。どの副業でも使える書き方・売り方の技術なら「4. ノウハウ」へ。

### 保存先

`02_Knowledge/01_ネタ/<ジャンル>/`の中に、情報源ごとに1ファイル(`<発信者名>.md`・`<本のタイトル>.md`)。複数のアカウントに共通するテーマは`共通テーマ.md`にまとめる。新しいネタほどファイルの上。ジャンルは内容で決める(恋愛・インテリア・ポケカなど)。

### 1ネタの書き方

```
### <ネタの名前>
- 副業: (恋愛Xなど)
- テーマ: (初デート・LINE・告白など)
- あるある: 読者が「自分のことだ」と思う場面を1〜2文で
- 新しい前提: 読者が「知らなかった」と思う事実や考え方(あれば)
- 使えるセリフ: 鍵カッコの具体的なセリフ(あれば)
- 切り口の候補: NG行動/成功行動/意外な事実/女性側の受け取り方 など、使えそうなもの
- フック案: 1行目の案を1〜2個
- 元データ: <01_Sourcesのファイルと投稿ID・動画ID・スクショ番号など>
- 使用: 未
```

### 拾い方

- 1件の情報から、投稿1本分になるネタを拾う。薄いものは無理に作らない
- 複数のアカウントで同じテーマが出ていたら、「共通テーマ」として1つにまとめ、何アカウントで出ているかを書く(多いほど読者の共感が取れているテーマ)
- 元ネタの言い回しは、そのまま投稿に使わない前提で書く。セリフも「こういう系統のセリフ」が分かれば十分
- 性的な内容、誇張、言い切りの一般化(「女性は必ず〜」)は拾わない
- 投稿に使ったネタは、Contentが「使用」に日付を書く

## 2. 分析

research-aiの報告を受け取ったら、`02_Knowledge/02_分析/<YYYY-MM-DD>_<テーマ>.md`に残す。

```
# <テーマ>(例: 恋愛Xアカウント7つの伸びる型)
- 副業: 
- 日付: 
- 調べたこと: 
- 分かったこと: (結論)
- 根拠: (データ・出典)
- データの限界: 
- これを受けて変えたこと: (ルール.mdをどう変えたか。変えていなければ「なし」)
```

同じテーマを調べ直した時は、新しいファイルを作り、古いファイルの一番上に「新しい分析: <ファイル名>」と書く(どう変わったか追えるように、古い方も残す)。

## 3. 成功と失敗

やってみて分かったことを、`02_Knowledge/03_成功と失敗/<副業>.md`の一番上に足す。research-aiの結果分析(投稿の振り返り)の報告や、りゅーじ君が話してくれた出来事から書く。

```
### <何の話か>(YYYY-MM-DD)
- やったこと: 
- 結果: (数字があれば数字で)
- なぜそうなったか: 
- 次どうする: 
- 他の副業でも使えそうか: 
```

うまくいったことも、失敗も、両方残す。失敗は同じことを2回しないためにある。

## 4. ノウハウ

外から学んだ、どの副業でも使える技術(1行目の作り方、返信欄への誘導、売り方など)。`02_Knowledge/04_ノウハウ/`に、情報源ごとに1ファイル。「何のための技術か」「どう使うか」「どの副業で使えそうか」を書く。

## 完了処理

- ネタを処理したら、`02_Knowledge/_管理/progress.json`の`processed_files`に、今回判断した分(使わなかったもの・除外したものも含む)を追記する。1回の実行で最大100件まで
- **今回足したものを、`05_System/更新履歴.md`の一番上に日付見出し(`## YYYY-MM-DD`)付きで簡潔に追記する**
- 最後に、種類ごとに足した数を簡潔に出力して終わる
