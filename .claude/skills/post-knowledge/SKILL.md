# 配信用ナレッジ

投稿のネタにするためのナレッジ。最初から「投稿に使う目線」で拾う。Contentはここからネタを選んで投稿を作る。

## 新着の洗い出し

`02_Knowledge/_管理/progress.json`の`processed_files`に無いものだけを対象にする。新着が無ければ何もせず終了してよい。対象を指定された時(「〇〇だけ」)は、それだけに絞ってよい。

対象ソース:
- `01_Sources/02_X/data/@<各アカウント>/posts.json`(投稿。`id`で処理済み判定)
- `01_Sources/02_X/data/@kw1ew/スクショ/*.jpg`(会話スクショ、画像のまま読む。OCR不要)
- `01_Sources/03_TikTok/data/*/transcripts/*.md`(TikTokの文字起こし)
- `01_Sources/04_YouTube/data/*/transcripts/*.md`(YouTubeの文字起こし)
- `01_Sources/01_Kindle/data/*/本文.md`(本、`kindle/<本のタイトル>`の形でprocessed_files照合)

## 除外と、使うかどうかの判断

**除外基準(問答無用で対象外)**: 煽情的・操作的なテンプレ投稿(釣り文句集、「女性を洗脳する」系の商材宣伝、性的体験の実況)、怪しい商材の宣伝、MBTI・血液型などの根拠のない分類。信頼している発信者(乾さん・はやとさん)の内容でも、この基準に該当するもの(自著宣伝・講師紹介など技術的内容がないものを含む)は除外する。

除外しなかったものは、読者が「あるある」「知らなかった」と思えて、投稿のテーマ・切り口・セリフになるかを見る。ならないものは保存しない。

**ジャンル**は内容を見て決める(恋愛・心理学・営業・インテリア・マーケなど)。「この情報源はこのジャンル専用」と決め打ちしない。フォルダが無ければ作ってよい。

## 保存先

`02_Knowledge/<ジャンル>/`の中に、情報源ごとに1ファイル(`<発信者名>.md`・`<本のタイトル>.md`)。複数のアカウントに共通するテーマは`共通テーマ.md`にまとめる。新しいネタほどファイルの上に書く。

書き方・構成の技術(1行目の作り方、返信欄への誘導、句読点の使い方など、どのジャンルでも使える書き方)は、ジャンルを問わず`02_Knowledge/01_Marketing/`に入れる。ジャンルのフォルダには「何を言うか」だけを置く。

## 1ネタの書き方

```
### <ネタの名前>
- テーマ: (初デート・LINE・告白など)
- あるある: 読者が「自分のことだ」と思う場面を1〜2文で
- 新しい前提: 読者が「知らなかった」と思う事実や考え方(あれば)
- 使えるセリフ: 鍵カッコの具体的なセリフ(あれば)
- 切り口の候補: NG行動/成功行動/意外な事実/女性側の受け取り方 など、使えそうなもの
- フック案: 1行目の案を1〜2個
- 元データ: <01_Sourcesのファイルと投稿ID・動画ID・スクショ番号など>
- 使用: 未
```

## 拾い方

- 1件の情報から、投稿1本分になるネタを拾う。薄いものは無理に作らない
- 複数のアカウントで同じテーマが出ていたら、「共通テーマ」として1つにまとめ、何アカウントで出ているかを書く(多いほど読者の共感が取れているテーマ)
- 元ネタの言い回しは、そのまま投稿に使わない前提で書く。セリフも「こういう系統のセリフ」が分かれば十分
- 性的な内容、誇張、言い切りの一般化(「女性は必ず〜」)は拾わない
- 投稿に使ったネタは、Contentが「使用」に日付を書く

## 完了処理・安全装置

- `02_Knowledge/_管理/progress.json`の`processed_files`に、今回判断した分(使わなかったもの・除外したものも含む)を追記する
- 1回の実行で処理する新着は**最大100件**まで。残りは次回に回す
- **今回足したネタを、`05_System/更新履歴.md`の一番上に日付見出し(`## YYYY-MM-DD`)付きで簡潔に追記する**
- 最後に、処理件数・足したネタの数を簡潔に出力して終わる
