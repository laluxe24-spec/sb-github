# 裏付けデータ取得(Research・パターン1)

Knowledgeとして既に保存済みの内容に、「これは○○という研究で裏付けられている」と言える学術的な根拠を後から調べて足すスキル。対象は、りゅーじ君が個人的に良いと思って集めている情報源(乾式.md・はやと式.md・本由来のファイルなど)由来の項目のみ。

**必ず`07_System/launchd/research_agent_prompt.md`を読み、そこに書かれている手順(`knowledge_meta.json`から未チェック項目の洗い出し→WebSearchで裏付け調査→`02_Sources/07_Documents/成長用裏付け.md`への追記→元のKnowledge項目に一言追記→`evidence_checked`の更新)にそのまま従う。**このSKILL.mdでは内容を複製しない(手順が更新された時に二重管理でズレるのを防ぐため)。

## 分析の考え方(このスキルが目指す形)

このスキルの役割は「論文を貼り付けること」ではなく、`knowledge-agent`が作った「こういう場面ではこう考える/こう動く」という判断・行動の型に対して、**「なぜそれが機能するのか」を学術的に裏付けること**。単に「研究があります」で終わらせず、以下をセットで残す。

- **誰の・どんな研究か**: 研究者・研究内容・サンプル数・結果・限界(`research_agent_prompt.md`手順3の通り、実際にWeb検索で確認できた範囲のみ)
- **どの場面・どの判断/行動に対応するか**: 元のKnowledge項目のどの「場面→考え方/行動」の型を補強するのか、対応関係を明記する
- **関連性**: 単独の研究の紹介で終わらせず、既存の根拠レベル(A〜D)や他の研究と矛盾しないか、関連する知見が他にもないかも確認する

これにより、りゅーじ君が「これは気持ちの問題じゃなく、実際にこういう仕組みで効く」と納得した上で、場面ごとの判断・行動に自信を持って使えるようにするのが目的。

## 手動実行時の違い

- 手動で頼まれた時は「無人実行モード」の自己紹介文言は不要。秘書エージェント自身が今その場で同じ調査ロジックを使っている、という扱いでよい。
- 「〇〇(特定の項目・ファイル)だけ裏付けを調べて」のように対象が指定された場合は、対象をその項目だけに絞ってよい(それ以外は無人実行の巡回に任せる)。
- 既存のKnowledge項目の主張内容そのものは書き換えない(裏付けの追記のみ)というルールは手動実行でも変わらない。
