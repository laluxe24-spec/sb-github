# 残し方(02_Knowledgeへの保存)

`02_Knowledge`は副業を成功させるための知見を貯める場所。副業ごとに分けずに1か所に貯め、全部のエントリに「どの副業で分かったことか」を書く(例: `副業: 恋愛`)。りゅーじ君個人の成長のためのもの(`03_MyKnowledge`)は、ここではなくmentor-aiの担当。

`04_Projects/<副業>/`のルールは「今の決まり」(結論だけ)。ルールが変わった時は、その理由・元になった分析や失敗をここに残す。

| 種類 | 何を | 保存先 |
|---|---|---|
| ネタ | 発信に使えるネタ | `02_Knowledge/01_ネタ/<ジャンル>/` |
| 分析 | 調べて分かったこと(伸びる型・競合・売れ筋・市場) | `02_Knowledge/02_分析/` |
| 成功と失敗 | やってみて分かったこと | `02_Knowledge/03_成功と失敗/<副業>.md` |
| ノウハウ | 外から学んだ、どの副業でも使える技術(書き方・売り方など) | `02_Knowledge/04_ノウハウ/` |

## 1. ネタ

**ネタにするのは、分析で「伸びた」と分かった投稿を優先する。** 全部の投稿をネタにしない(どれが強いか分からなくなるため)。

- 除外(問答無用): 煽情的・操作的なテンプレ投稿(釣り文句集、「女性を洗脳する」系の商材宣伝、性的体験の実況)、怪しい商材の宣伝、MBTI・血液型などの根拠のない分類、性的な内容、誇張、言い切りの一般化(「女性は必ず〜」)
- 保存先: `02_Knowledge/01_ネタ/<ジャンル>/`の中に、情報源ごとに1ファイル(`@<アカウント>.md`・`<本のタイトル>.md`)。複数のアカウントで共通するテーマは`共通テーマ.md`にまとめ、何アカウントで出ているかを書く。新しいネタほどファイルの上
- 元ネタの言い回しは、そのまま投稿に使わない前提で書く
- 処理した元データは`02_Knowledge/_管理/progress.json`の`processed_files`に追記する(使わなかったものも含む)

```
### <ネタの名前>
- 副業: (恋愛など)
- テーマ: (初デート・LINE・告白など)
- あるある: 読者が「自分のことだ」と思う場面を1〜2文で
- なぜ伸びたか: (数字つき。例: 表示回数32万・普段の平均の5倍・続きの読まれ率14%)
- 使えるセリフ: 鍵カッコの具体的なセリフ(あれば。自分の言葉で書き直したもの)
- 切り口の候補: NG行動/成功行動/意外な事実/女性側の受け取り方 など
- フック案: 1行目の案を1〜2個
- 元データ: <01_Sourcesのファイルと投稿IDなど>
- 使用: 未
```

投稿に使ったネタは、content-aiが「使用」に日付を書く。

## 2. 分析

`02_Knowledge/02_分析/<テーマ>.md`に残す。同じテーマを調べ直したら、新しいファイルを作らずそのファイルを書き換える(古い版はgitの履歴に残る)。

```
# <テーマ>(例: 恋愛Xアカウントの伸びる型)
- 副業:
- 最終更新: YYYY-MM-DD
- 今回やった分析:
- 分かったこと: (数字つき)
- 提案: (次に取り入れること)
- この分析の甘いところ・次に試したい切り口:
- 出典:
```

## 3. 成功と失敗

やってみて分かったことを、`02_Knowledge/03_成功と失敗/<副業>.md`の一番上に足す。うまくいったことも失敗も両方残す。

```
### <何の話か>(YYYY-MM-DD)
- 副業:
- やったこと:
- 結果: (数字があれば数字で)
- なぜそうなったか:
- 次どうする:
- 他の副業でも使えそうか:
```

## 4. ノウハウ

外から学んだ、どの副業でも使える技術(1行目の作り方、返信欄への誘導、売り方など)。`02_Knowledge/04_ノウハウ/`に情報源ごとに1ファイル。「何のための技術か」「どう使うか」「どの副業で使えそうか」を書く。

- 足したものを`05_System/更新履歴.md`の一番上に日付見出し(`## YYYY-MM-DD`)付きで簡潔に書く
