# Kindle(本)

Kindleアプリで本を開き、自動でページ送りしながらスクショを撮り、OCR(画像から文字を読み取る処理)で`本文.md`を作るところまでがこの手順。指示があったら、手順6のスクショ削除以外は確認を取らずに最後まで進めてよい。

OCRは「本の考え方が分かればいい」方針なので、一字一句の精度にはこだわらない。多少の誤字・重複・順序の乱れは気にせず先へ進む。

## フォルダ
```
01_Sources/01_Kindle/
├── scripts/
│   ├── kindle_screenshot.py       スクショ撮影(全ての本で共通)
│   ├── ocr_book.py                縦書きの本用OCR(tesseract jpn_vert)
│   ├── ocr_book_horizontal.py     横書きの本用OCR(macOS Vision)
│   └── venv/                     スクリプト用のPython環境
└── data/<本のタイトル>/
    ├── screenshots/              ページ画像(OCRとナレッジ化が終わったら消してよい)
    └── 本文.md                   OCRで書き起こした全文(誤字混じり)
```

## 手順0: 本をKindleアプリで開く(ユーザー不在時は自力で操作する)

ユーザーが手元にいない場合、Claude自身がKindleライブラリの本棚画面を操作して対象の本を開くことができる。

1. `screencapture -x -o -l <windowID>` でKindleウィンドウをキャプチャし、Readツールで画像を見て本棚の中から対象の表紙の位置を目視で特定する。
2. `Quartz.CGEventCreateMouseEvent` で、カーソルを移動→ボタンダウン→ボタンアップの順にイベントを送ってダブルクリックする(単に位置を指定してdown/upするだけでなく、`kCGEventMouseMoved`で先にカーソルを実際に動かしておくことが重要。動かさずにいきなりクリックイベントだけ送ると反応しないことがある)。
3. 未ダウンロードの本は1回目のダブルクリックでダウンロードが始まる(「開くことができます」という進捗表示に変わる)。数秒待ってダウンロード完了(チェックマーク)を確認してから、もう一度同じ場所をダブルクリックすると本が開く。
4. 座標計算の注意点: `screencapture -l` で得られる画像は「ウインドウの実サイズの2倍(Retina)」のピクセル画像。画像上で読み取った座標をクリックに使う場合は **必ず2で割ってから、ウインドウの原点(X,Y)を足す**((image_x/2 + window.X, image_y/2 + window.Y))。この/2を忘れると全く見当違いの場所をクリックしてしまう(実際に一度この間違いをして「戻る」ボタンを押せなかったことがあった)。

### 本を1ページ目(表紙)に戻す方法

読みかけの本を開くと前回の続きから表示される。最初から撮影するには1ページ目に戻す必要があるが、ページ送りの矢印キーで最初まで戻るのは非効率(何十回も必要)。以下の方法が確実:

1. 画面中央あたりをクリックしてツールバー(上部バー・下部のページ位置スライダー)を表示させる。
2. 左上の目次アイコン(≡のようなアイコン、ツールバー左から2番目)をクリックしてTOCパネルを開く。
3. パネル内でスクロールし、リストの一番上にある「表紙」(または本のタイトルの直下にある先頭項目)をクリックすると、1ページ目にジャンプできる。
4. 「表紙」の項目が無い本(目次が「目次」から始まっている場合など)は、一覧の一番上の項目をクリックしてから、必要に応じて矢印キーを数回押して先頭まで戻る。

**下部のページ位置スライダーをドラッグする方法は本によって挙動が不安定(効かない/意図した方向と逆に動く)なので、上記のTOCパネル経由の方法を優先すること。**

なお、縦書きの本ではページ送りの「進む」方向が右→左(左矢印キーが「次のページ」)になっている場合があり、スライダーの左右の意味もそれに応じて逆になっていることがある。横書きの本は通常通り右方向・右矢印キーが「次」。

## 手順1: キャプチャ

Kindleアプリで対象の本を開いた状態で実行する。

```
cd 01_Sources/01_Kindle/scripts
./venv/bin/python3 kindle_screenshot.py <本のタイトル>
```

- 第1引数(本のタイトル): 省略すると `untitled` フォルダになるので、複数の本を扱うときは必ず指定する。
- 第2引数(ページ数上限、省略可): 通常は指定不要。デフォルトで5000ページ分の上限があるが、これは「本当に何かおかしくなった時の安全装置」に過ぎず、実際にはページが変化しなくなった時点(=最終ページ)で自動停止する。5000ページを超えるような本は現実的にまず無いので、通常は本のタイトルだけ渡せばよい。
- 出力先は自動的に `01_Sources/01_Kindle/data/<本のタイトル>/screenshots/` になり、同じフォルダに `capture.log`(実行ログ)も自動生成される。

**最終ページ自動停止**: ページ送り後に2回連続で画面が変化しない場合、最終ページに到達したとみなしてループを打ち切り、重複した最後の1枚も自動削除する。ページ数上限を指定する必要がないため、「本のページ数を事前に知らないと何回指定すればいいか分からない」「上限を低く指定すると最後まで撮り切れない」「上限を大きくしすぎると最終ページで無駄な重複が大量発生する」といった問題がすべて解消されている。万一、上限ページ数に到達しても最終ページを検出できなかった場合は、`capture.log`に警告が出るので、その場合だけページ数上限を増やして再実行する。

なお、縦書きの本では最初「右矢印キーではページが変わらない」ことがある(そのページが本のレイアウト上、右方向には送れない場合など)。その場合スクリプトは自動で左矢印キーに切り替えて続行する。

キャプチャ後は `capture.log` を一度確認し、「右矢印キーではページが変わりませんでした」のような記録がないか見ておく(途中でキーが効かなくなった痕跡がないかの確認)。

**目次ページなどでページが進まなくなる問題への対処**: 目次(リンク付き)のページでは、矢印キーがページ送りではなくリンク間のフォーカス移動として扱われ、ページが変化しなくなることがある。スクリプトはこれを検出すると、ウインドウ左側の余白(コンテンツ枠の外、リンクもブックマークリボンも無い場所)を一度クリックしてフォーカスを外し、再試行する(最大3回)。

**注意(固定レイアウトの本)**: 固定レイアウトの本(マンガ形式・ワークブック形式など、章の見出しにパンくずリンクが付いているタイプ)では、この「余白クリックによる回復」がうまく機能せず、逆にクリックが章見出しの見出しリンク(例:左上の「Part2 ◯◯」というパンくず表示)に当たってしまい、本の別の場所(Partの先頭など)に意図せずジャンプしてしまうことがあった。この場合、キャプチャされた連番ファイルの中に、本の後半のページと前半のページが入り混じって記録されてしまう。

この問題が起きた場合の対応方針:
- 各ページに表示されている実際のページ番号(丸数字など)を手がかりに、内容の重複・前後関係を判断する。
- ユーザー方針(「OCRの精度や完全性より、本の考え方が分かればいい」)に従い、多少の重複や順序の乱れがあっても、後続のOCR・ナレッジ化でそのまま処理して問題ない(ナレッジ化の時にその旨を断り書きしておく)。
- 完全な内容が必要な場合のみ、手順0の方法で該当本を先頭に戻し、ページ数上限を低めに指定して(例: 実際のページ数+10程度)再キャプチャすることを検討する。

## 手順2: 重複画像の削除(2段階)

`data/<本のタイトル>/screenshots/` フォルダ内の重複を、以下の2段階で検出・削除する。**削除はユーザーに逐一確認を取らずに自動で行ってよい**。ただし何を(何枚)削除したかは結果として簡潔に報告する。

### 2-1. MD5完全一致での削除
全画像のMD5ハッシュを計算し、完全に同一のバイト列を持つファイルをグループ化する。Kindleウィンドウがフリーズした/フォーカスを失った/最終ページで同じ画面が繰り返し撮影された、といったケースで発生する完全一致の重複を検出する。各グループの最初の1枚だけ残して残りを削除する。

### 2-2. 知覚的ハッシュ(dHash)での近似重複の削除
MD5だけでは、同じページでもウィンドウサイズが異なる撮影(ピクセルは微妙に違うが内容は同じ)による重複を見逃す。`venv`にインストール済みのPillowを使い、各画像をグレースケール化・縮小してdHash(差分ハッシュ)を計算し、ハミング距離が近い画像同士をペア/クラスタとして検出する。

**重要な落とし穴**: dHashは「章の扉ページ」(例:「第一夜」「第二夜」のような、白背景に短い数文字だけが同じ位置に配置されたページ)に対して誤検出を頻発する。実際の文字内容が違っても、大まかなレイアウト(余白と文字ブロックの位置)がほぼ同じため、ハミング距離が0〜2という極めて近い値になってしまう。過去に、全く異なる5つの章(第一夜〜第五夜)やあとがきページが「同じ重複グループ」として誤って一つにまとめられたことがあった。

そのため、**dHashで検出した候補は必ずReadツールで画像を実際に開いて目視確認してから削除すること**。特に以下のページタイプは要注意:
- タイトルページ、章扉ページ(短文+大量の余白)
- 本文が少ないページ全般

本文がぎっしり詰まった通常のページ同士であれば、dHashの距離0はほぼ確実に本当の重複(同一ページの再撮影)と判断してよい。

## 手順3: 後片付け(capture.log)

重複整理が完了したら、`capture.log` は用済みなので削除する。診断用の一時ファイルであり、整理作業が終わった後は残しておく必要がない。

## 手順4: OCR(縦書き・横書きでスクリプトを使い分ける)

本が縦書きか横書きかで使うスクリプトが異なる。最初の数ページを見て判断する。

### 縦書きの本 → `ocr_book.py`(tesseract jpn_vert)

**注意**: macOS標準のVision(pyobjc-framework-Vision)は縦書きの日本語テキストを検出できない(横書きのUI文字(タイトルバー・進捗%など)しか拾えない)。90度回転させても文字自体が横倒しになるだけで読めない。そのため、縦書き対応の`tesseract`(`jpn_vert`言語モデル)を使う。

初回のみ、Homebrewで`tesseract`と`tesseract-lang`(`jpn_vert`を含む)をインストールする:
```
brew install tesseract tesseract-lang
```

インストール後、以下を実行する:
```
cd 01_Sources/01_Kindle/scripts
python3 ocr_book.py <本のタイトル>
```
`data/<本のタイトル>/screenshots/` の各画像を`tesseract -l jpn_vert --psm 5`でOCRし、UI由来のノイズ行(「Kindle」「◯%」「読書の速さを測定中」など)を除去した上で `data/<本のタイトル>/本文.md` にページ区切り付きでまとめる。

**精度の傾向**: 通常の本文ページ(会話文など)はかなり良好に読み取れる。一方、章の扉ページ(大きな文字+大量の余白)や表紙イラストのページは文字化けしやすい(該当ページ数としては少数派)。

### 横書きの本 → `ocr_book_horizontal.py`(macOS Vision)

横書きの本(ワークブック・実用書など)は、tesseractより高精度なmacOS標準のVision frameworkが使える。

```
cd 01_Sources/01_Kindle/scripts
./venv/bin/python3 ocr_book_horizontal.py <本のタイトル>
```
同じく `data/<本のタイトル>/本文.md` に出力する。Visionは横書きテキストなら非常に高精度。

いずれの方式でも、ユーザーは「最終的に本の考え方が分かればよく、OCRの一字一句の精度にはこだわらない」という方針なので、多少の誤字・文字化けは気にせず次の手順に進んでよい。

## 手順5: ナレッジにする

`本文.md`ができたら、my-knowledgeスキル(自分用)・post-knowledgeスキル(配信用)でナレッジにする。分量が多いので、Agentツールに任せて会話を汚さないほうがいい。

## 手順6: スクショの削除

ナレッジ化まで終わったら、`data/<本のタイトル>/screenshots/`は消してよい(必要になったら撮り直せばいい)。**ただし消す前に必ずりゅーじ君に確認する**(正常なページも含めた本体データの削除のため)。
