## 交通費申請の自動入力手順(八木さん・月次)

### 目的
「イベントシフト」から八木さんの出勤日・勤務地を抽出し、「交通費申請＿八木さん」スプレッドシートの該当月タブに、西国立からの往復運賃を自動入力する。

### 対象ファイル
- **イベントシフト**(読み取り専用・絶対に編集しない): file ID `1t0pdsRot057Tq8LM3EOC9epYM-bOwEQ2a_dLyPTJgIc`
- **交通費申請＿八木さん**(編集OK): file ID `19-bKpPgWJe7FY8-9VeCJq_Yhj6nMqeXMGSOwBUe8Uok`

### 実行条件
- 対象月のシフトタブ(イベントシフト)、または対象月の交通費申請タブ(交通費申請＿八木さん)のどちらかが存在しない場合は、**実行しない(未実行)**。ユーザーにその旨を伝えて終了する。

### 手順

#### 1. シフトデータの抽出
1. Google Driveコネクタの `download_file_content` で両スプレッドシートを xlsx 形式(`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)でダウンロードし、base64をデコードしてローカルファイル化する。
2. Python + openpyxl で対象月のシートタブ(例: `202609`)を読み込む。
3. シフト表は「日付ヘッダー行」+「勤務地セル(結合セル)」+「その下のスタッフ名セル」という構造。openpyxlの `merged_cells.ranges` を使い、結合セルの値を「その列範囲に効く勤務地」として管理し、各スタッフ名セルの列から日付・勤務地を特定する。
4. 抽出結果は「出勤日数」の合計値(シフト表内の集計セル)と突き合わせて検算する。

#### 2. 運賃の決定
- 「交通費申請＿八木さん」の前月以前のタブから、駅名ごとの往復運賃を参照する(直近月を優先)。
- 勤務地名(例:アルカキット錦糸町、池袋東口/西口、サンシャインシティ池袋)は実際の最寄り駅(錦糸町、池袋など)に読み替えて運賃を当てはめる。
- 過去データにない新しい勤務地で最寄り駅が分からない場合は、推測せず、その行の「到着」と「料金」だけ空欄のまま残す(他の列(月/日/項目/出発/片道往復/領収書有無)は通常通り入力する)。ユーザーが後で手動で埋める。
- 「カード稼働」「ST稼働」のような、駅名・場所ではなく業務種別を表す不規則な表記(下記「イベント種別の見分け方」参照)の日も同様に、到着・料金は空欄のままにして手入力に任せる。

#### 3. スプレッドシートへの入力(重要な注意点)
「交通費申請＿八木さん」への実際のセル入力は、Google Drive連携(コネクタ)にはセル書き込みAPIが無いため、**Claude in Chrome(ユーザーの実ブラウザ・ログイン済み)を使ったブラウザ自動操作**で行う。

つまずきポイントと対策:

1. **日本語(CJK)テキストは `type` アクションで直接入力できない。**
   - 数字やASCII文字は問題なく入力できるが、日本語を`type`で送ると何も入力されずに終わる(IME関連の制限とみられる)。
   - 対策: `=UNICHAR(38651)&UNICHAR(36554)` のように、Unicodeコードポイントを `UNICHAR()` 関数で連結する数式を入力する。Pythonの `ord(c)` で各文字のコードポイントを取得できる。改行が必要な場合は `CHAR(10)` を挟む。
   - 数式のまま残るが表示上は正しい日本語になるので機能上は問題ない。

2. **クリック座標がスクリーンショット間でズレることがある。**
   - 一度、ヘッダー行を誤って上書きしてしまう事故が発生した(セル座標のズレが原因)。
   - 対策: 一度確実な位置(例:キーボードで `Ctrl+Home` → 矢印キーで目的セルへ)に到達したら、その後は **クリックではなくキーボード操作(Tab/Enter/矢印キー)で移動する**。Tabで右へ、Enterでその行の入力開始列に戻って次の行へ、という規則性を使うと安全。
   - 万一ヘッダー等を誤って上書きした場合、Ctrl+Zの取り消しが効かないことがあるため、正しい値を同じくUNICHAR数式で入力し直して復元する(バージョン履歴に頼れない場合の保険)。

3. **入力する列の並び(交通費申請シート)**
   - A:月(タブ先頭行に既存)/ B:日 / C:項目(電車) / D:出発(西国立) / E:到着(駅名) / F:片道/往復(往復) / G:領収書有無(無) / H:料金(運賃) / I:インボイス未対応チェック(空欄のまま) / J:税率(空欄のまま)

#### 4. 対象外(ユーザーが手動で行う範囲)
- 電車遅延等で経路が変わった場合の修正
- 月末の最終チェック
- 手入力が必要なイレギュラーな経費

## Googleカレンダーへの勤務地登録(八木さん・月次)

- 対象カレンダー: 八木さんの共有カレンダー(calendar id `r.yagi1121@gmail.com`)
- 対象月のイベントシフトから抽出した出勤日・勤務地をもとに登録する。
- **イベント種別**: 通常の終日イベント(DEFAULT)。Googleカレンダーの「勤務場所(Working Location)」専用タイプは使わない。
- **重要: allDay終日イベントの日付ズレに注意**。`create_event` で `allDay: true` にして `startTime`/`endTime` を `T00:00:00+09:00` で渡すと、実際には1日前の日付で登録されてしまう(UTC変換後に日付だけ切り出される仕様のため)。対策として、時刻部分を `T00:00:00` ではなく `T09:00:00+09:00` にする(9時JST=0時UTCとなり、同じ日付のまま処理される)。登録後は必ず `list_events` で実際の日付を確認し、ズレていないか検算する。

#### イベント種別の見分け方(`i.` を付けるかどうか)
- `i.` = イズナ(自社)のイベント稼働という意味。通常のイベントシフト上の勤務地(アルカキット錦糸町、池袋東口 など)はこれに該当するので `i.` を付ける。
- 「カード稼働」: イベントではなく、社長と一緒にやっている別事業。`i.` を付けず、タイトルは「カード稼働」だけにする。
- 「ST稼働」: ST社という別会社のイベントに出る場合。`i.` を付けず、タイトルは「ST稼働」だけにする。
- 他にも同様の不規則な(駅名・場所ではなく業務種別を表す、いつもと違う)表記が出てきたら、質問せず `i.` を付けずイベントシフトの表記通りそのままタイトルにして登録してOK。その分の経費(到着・料金)はユーザーが手入力するので空欄のままにする。

#### イベントタイトルの形式(通常のイベント稼働の場合)
- `i.` + イベントシフトに書かれている勤務地名(またはイベント名)を、**省略・短縮せずそのまま**使う。例: `i.アルカキット錦糸町`、`i.池袋東口`、`i.池袋西口`、`i.サンシャインシティ池袋`(「サンシャイン池袋」のように短縮しない)。
- **まとめ方**: 連続する日付で同じ勤務地が続く場合は、1日ずつではなく1つの期間イベント(開始日〜終了日)にまとめて登録する(例: 9/8〜9/11が池袋東口なら1件のイベントにする)。
- イベントシフトは登録作業中も参照のみ。内容に誤りがあるように見えても絶対に編集しない。
- 実行前に、対象月分がすでに登録済みでないか `list_events` で必ず確認し、重複登録を避ける。

### 自動化の限界(2026年9月時点)
- クラウドルーティン(`/schedule`)はサンドボックス環境で動くため、ユーザーの実ブラウザ(Claude in Chrome)にアクセスできず、この方法でのスプレッドシート入力ができない。
- ローカルの `CronCreate` はセッション内のみ有効で、セッションを閉じると消え、7日で自動失効するため、月次の永続的な自動実行には使えない。
- 現状、確実な方法は「毎月1日にユーザーからメッセージで実行を依頼する」こと。
