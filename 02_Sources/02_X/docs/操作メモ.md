# 操作メモ(Xアカウントのスクショ収集・再現手順)

このメモは、Claude自身が次回以降のセッションでも同じ作業を再現できるようにするための手順書。
複数のXアカウントを解析する前提のフォルダ構成になっている。

## フォルダ構成
```
02_Sources/02_X/
├── docs/                共通ドキュメント(このファイル、README)
├── scripts/              共通の収集スクリプト(全アカウント共通で使い回す)
└── data/
    └── @<アカウント名>/   アカウントごとの生データ(スクショ収集の場合とpost収集の場合で中身が異なる)
        ├── スクショ/       (スクショ収集の場合)絞り込み後の採用画像(連番.jpg)
        ├── manifest.json  (スクショ収集の場合)各画像の元ツイートURL {file, tweet_url}
        └── posts.json     (post収集の場合)投稿データ
```
アカウント名フォルダには見分けやすいよう先頭に`@`を付ける(例: `data/@kw1ew/`)。新しいアカウントを解析する場合は `data/@<アカウント名>/` を追加すればよい。

分析結果(文字起こし・パターン分析など)は、このフォルダ内の`knowledge/`は使わず、`03_Knowledge/03_Romance/`(ジャンル別)に直接まとめる。

## 手順

### 1. ログイン(auth.jsonのセッションが切れている場合)
```
node login.js
```
ヘッドありのブラウザが開くので、ユーザー本人がその場でXにログインする。`auth_token`のCookieを検知したら自動で `auth.json` に保存して終了する(最大10分待機)。

### 2. 次のN件を収集する
```
node collect_media.js 100
```
`collect_media.js`内の`USERNAME`は`kw1ew`に固定でハードコードされており、コマンドライン引数はN件数のみを受け取る(アカウント名は渡さない)。誤って`node collect_media.js kw1ew 100`のようにアカウント名も渡すと、Nが`NaN`になりスクレイプが即0件で終わる(2026-09-18に発覚・修正済み。2026-09-16のログで「新着0件」となっていたのも、実際はこのバグが原因だった可能性が高い)。
- `https://x.com/<アカウント名>/media?filter=photo` のグリッドをスクロールしながら、`processed_ids.json` に無い(=未取得の)写真投稿を新しいものから順にN件集める
- ダウンロードした画像は `scripts/screenshots_batchN/`(生データ、まだ絞り込み前)に保存され、`processed_ids.json` が更新される
- 複数アカウントを扱う場合は `processed_ids.json` をアカウントごとに分けるか、tweetIdでの重複判定が壊れないよう管理する

### 3. 絞り込み(3段階)
`scripts/screenshots_batchN/` の画像を1枚ずつ見て、以下の基準で仕分ける。

**残す**
- 実際の2人の会話で、口説き・ラポール構築のテクニックを示しているもの(オープニング、テンポの良い掛け合いなど)。地の文の画面キャプチャ(LINE/DM等のトーク画面そのもの)であること。

**除外**
- 電話を手に持って撮影した写真(スクショではなく撮影写真)
- 本の表紙・ニュース動画・食事写真など、チャット画面と無関係な画像
- 性的な体験報告(「報告です」「結果◯」形式、性的内容の詳細な描写、ヌード・際どい写真を含むもの)
- 感想・レビュー(お客さん・受講生が講座や本人を褒めているだけのメッセージ)
- ダウンロード失敗(空/破損)ファイル
- 対象アカウントの実際のマッチングアプリ画面ではないスクショ(LINEアプリの画面、汎用アイコン(花・惑星等)が相手アイコンになっているもの、出どころ不明の断片的なやり取り)。本人と相手の実トーク画面ではないため、口説きテクニック実例として不適切。

判断に迷う場合は「実際の口説き会話のテクニック例になっているか」を基準にする。

#### 除外事例(kw1ew, 2026-09-13)
以下は`data/@kw1ew/スクショ/`に混入していたが、Tapple上の会話ではなく出どころが異なると判断し削除した(manifest.jsonからも削除済み):
- 旧011.jpg: LINE画面(花アイコン)でのパパ活ネタのやり取り
- 旧012.jpg: LINE画面(惑星アイコン)でのアイスクイズのやり取り
- 旧053.png: LINE画面(鉛筆アイコン)での断片的な2行だけのやり取り(「犯して」「リライトして」)

これらはいずれもTapple特有のUI(相手のプロフィール写真アイコン、吹き出しの配色)ではなく、汎用アイコン+LINE風UIだった点が判別の決め手。

#### LINE移行後の会話についての判断(kw1ew, 2026-09-18)
batch8では、相手のアイコンが実写真(赤塗り済み)のLINE画面(マッチングアプリでマッチ後、LINEに交換して続いている実際の会話とみられるもの)が複数枚あった。汎用アイコンではなく実写真だったため判断に迷ったが、「対象アカウントの実際のマッチングアプリ画面ではないスクショ」という基準の大枠に従い、除外側に倒した。この解釈(LINE画面は実写真アイコンでも一律除外)に確信が持てているわけではないため、次回の週次チェックで方針が合っているか確認してほしい。

### 4. data/@<アカウント名>/スクショ/ に統合する
1. 絞り込み後に残った画像を `data/@<アカウント名>/スクショ/` にコピーする
2. 既存ファイルの最大番号の続きから連番を振り直す(例: 091.jpg, 092.jpg…)
3. `data/@<アカウント名>/manifest.json` に `{file: "スクショ/xxx.jpg", tweet_url}` の形式で追記する(元のバッチのmanifest.jsonからtweet_urlを引く)
4. `scripts/screenshots_batchN/` の生データは用済みなので削除してよい

### 5. 完了後
- このファイルの「<アカウント名>の現在の状態」セクションを更新する(最新の連番の最大値など)。新規アカウントの場合はセクションごと追加する。
