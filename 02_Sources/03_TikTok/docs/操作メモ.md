# 操作メモ

## トリガー
「TikTokの動画を文字起こしして」「このTikTokをナレッジに入れたい」のような指示が来たら、このプロジェクトの `scripts/transcribe.py` を使う。

## 手順
1. ユーザーからTikTok動画のURL(個別動画、`https://www.tiktok.com/@アカウント名/video/数字` の形式)を受け取る。プロフィールURLしか無い場合は、対象の動画を1本ずつ確認してから進める(CLAUDE.mdの「一つずつ確認」方針に従う)。
2. 以下を実行する。

```bash
cd /Users/ryuji/sb-mac/02_Sources/03_TikTok
python3 scripts/transcribe.py "https://www.tiktok.com/@アカウント名/video/数字"
```

3. 大量(数十〜数百本)にまとめて処理したい場合は、URLを1行1つのテキストファイルにしてこちらを使う。

```bash
python3 scripts/transcribe.py --file urls.txt
```

4. 完了すると `data/@アカウント名/` 以下に以下が生成される(02_X/data/@アカウント名/ と同じ、アカウント別フォルダ構成)。
   - `transcripts/<video_id>.md`: 文字起こし(フロントマターに url・投稿者・タイトル・投稿日を含む)
   - `manifest.json`: そのアカウントで収集した動画の一覧(file・video_url・title・upload_date)。動画を追加するたびに自動更新される
   - 音声ファイルは文字起こし完了後に自動削除される(容量節約のため、音声・動画ファイルは残さない方針)
5. 文字起こしの中身をユーザーと確認し、OKが出たら要点を整理して `03_Knowledge/<ジャンル別フォルダ>` に知識としてまとめる(このプロジェクト内には知識フォルダを作らない)。

## 依存ツール
- `yt-dlp`(brew): 音声ダウンロード(動画は落とさず音声トラックのみ取得して高速化)
- `ffmpeg`(brew): yt-dlpの音声抽出処理で内部的に使用
- `mlx-whisper`(pip, Apple Silicon専用): 音声認識。モデルは `mlx-community/whisper-large-v3-turbo` を使用(速度と精度のバランス重視)

## 過去にハマった注意点・改善履歴
- TikTokの動画URLに直接ブラウザでナビゲートすると、自動アクセスとみなされてエラーページや動画一覧の読み込み失敗が起きることがあった。ブラウザ操作でTikTokにアクセスするのは避け、このスクリプト(yt-dlp)経由でのダウンロードに統一する。
- 初回実行時、Whisperモデル(数百MB〜1GB程度)が自動でダウンロードされるため、少し時間がかかる。
- 大量処理(137本)を1つのPythonプロセス内でループ実行したところ、Whisperモデルの読み込みが蓄積してメモリ不足になりOS(macOS)にプロセスをkillされた。対策として以下を実装済み:
  1. 動画全体ではなく音声のみダウンロードする(`-x --audio-format wav`)ことで、ダウンロード時間・ディスクI/Oを削減
  2. 空きメモリが800MBを下回ったら、次の動画に進む前に自動で待機する(`wait_for_memory`)
  3. `--file`実行時は10本ごとにPythonプロセスを立て直す(`CHUNK_SIZE`)。1本ごとの立て直しはモデル再読み込みのオーバーヘッドが大きく、逆にずっと同じプロセスだとメモリが蓄積するため、10本という単位でバランスを取っている
- 大量処理を始める前は、Chromeのタブ整理やClaudeデスクトップアプリの終了など、他の重いアプリを閉じておくとメモリ不足で落ちにくくなる。
