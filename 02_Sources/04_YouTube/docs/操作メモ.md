# 操作メモ

## トリガー
「YouTubeの動画を文字起こしして」「この動画をナレッジに入れたい」のような指示が来たら、このプロジェクトの `scripts/transcribe.py` を使う。

## 手順
1. ユーザーからYouTube動画のURL(`https://www.youtube.com/watch?v=...` または `https://youtu.be/...`)を受け取る。
2. 以下を実行する。

```bash
cd /Users/ryuji/sb-mac/02_Sources/04_YouTube
python3 scripts/transcribe.py "https://youtu.be/xxxxxxxxxxx"
```

3. 大量にまとめて処理したい場合は、URLを1行1つのテキストファイルにしてこちらを使う。

```bash
python3 scripts/transcribe.py --file urls.txt
```

4. 完了すると `data/@チャンネル名/` 以下に以下が生成される(03_TikTok/data/@アカウント名/ と同じ、チャンネル別フォルダ構成)。
   - `transcripts/<video_id>.md`: 文字起こし(フロントマターに url・チャンネル名・タイトル・投稿日を含む)
   - `manifest.json`: そのチャンネルで収集した動画の一覧(file・video_url・title・upload_date)。動画を追加するたびに自動更新される
   - 音声ファイルは文字起こし完了後に自動削除される(容量節約のため、音声・動画ファイルは残さない方針)
5. 文字起こしの中身をユーザーと確認し、OKが出たら要点を整理して `03_Knowledge/<ジャンル別フォルダ>` に知識としてまとめる(このプロジェクト内には知識フォルダを作らない)。
   - **YouTubeの実践者ノウハウ動画は「個人ソースの記録」として扱う**: 学術的な裏付けが無い個人の体験談(例: 「月50万達成しました」系のノウハウ動画)は、`research-topic`スキル(学術論文限定)の対象にはしない。`はやと式.md`・`乾式.md`と同じ「情報源(発信者)ごとの専用ファイル」形式で`03_Knowledge`に保存し、査読の無い1事例であることが分かるようにする。

## 依存ツール
- `yt-dlp`(brew): 音声ダウンロード(動画は落とさず音声トラックのみ取得して高速化)
- `ffmpeg`(brew): yt-dlpの音声抽出処理で内部的に使用
- `mlx-whisper`(pip, Apple Silicon専用): 音声認識。モデルは `mlx-community/whisper-large-v3-turbo` を使用(速度と精度のバランス重視)

## 過去にハマった注意点・改善履歴
- YouTubeは1本の動画がTikTokより長い(数分〜1時間超)ことが多いので、文字起こしに数分〜数十分かかることがある。気長に待つ。
- 大量処理時のメモリ対策(空きメモリ800MB未満で待機、10本ごとにプロセス再起動)は03_TikTokの`transcribe.py`と同じ仕組みを流用している。詳しい経緯は`02_Sources/03_TikTok/docs/操作メモ.md`を参照。
