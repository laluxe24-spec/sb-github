# AI組織図

sb-macで動くAI全体の基本構造。

## 基本

中心になるのは秘書エージェント。りゅーじ君からの依頼・会話・新しい情報・蓄積したKnowledgeを見て、自分で処理するか、機械的な作業をさせるか、サブエージェントを呼ぶかを判断する。

## 秘書エージェント

考える・判断する・指示する・統合する。単なる受付や振り分け役ではなく、状況を理解した上で自分でできることは自分で処理する。

## 機械的な作業(AI判断は基本不要)

決められた処理を実行するだけの仕事。情報の取得(X・TikTok・Threads・Instagram・Web・Kindleなど)、ファイルの整理・移動、決められた形式への変換など。launchd・API・Playwright・yt-dlpなどを使って自動実行する。

## サブエージェント(必要なときだけ呼ぶ、4人)

専門的な判断・分析・制作が必要なときだけ、秘書エージェントが呼び出す。常に独立して動いているわけではない。指示書は`.claude/agents/`にある(Claude Codeが正式にサブエージェントとして呼べる場所)。

人はプロジェクトごとに増やさない。4人は全プロジェクト共通で、プロジェクトごとの違い(ゴール・「結果」の測り方・ターゲット・100点の基準)は`05_Projects/<プロジェクト>/ルール.md`に書き、各担当が毎回それを読んで動く。

- **Research(調べる・分析する)**: 論文・Web・伸びてるアカウント探し・集めたデータの分析・自分の投稿の反応分析。媒体やモードごとの違いは手順書を切り替えて対応する → `.claude/agents/research.md`
- **Knowledge(溜める)**: 集めたものを使える知識にして、正しい棚に置き、統合し、Contentが引きやすい形にしておく → `.claude/agents/knowledge.md`
- **Content(作る)**: ナレッジとプロジェクトのルールから、投稿・記事・台本などを作る → `.claude/agents/content.md`
- **QA(出す前に止める)**: 作ったものの採点、ナレッジの確認、新しいスキル・ルールの矛盾チェック、事故防止 → `.claude/agents/qa.md`

サブエージェント同士は直接やり取りできない。受け渡しは必ず秘書エージェントが行い、その中で完結させる(途中経過でりゅーじ君を都度巻き込まない)。

新しいことを始める時(例: ポケカ)は人を増やさず、秘書エージェントがResearchに調べさせた上で、`05_Projects/<プロジェクト>/ルール.md`と必要なスキルを作る(りゅーじ君の確認が必要)。

## 全体の流れ

```
情報・依頼が入る
↓
秘書エージェントが判断(自分でやる/機械的作業/サブエージェント)
↓
Research(調べる) → Knowledge(溜める)
↓
Content(作る) → QA(チェック、不合格ならContentに差し戻し)
↓
りゅーじ君に提出 → 発信
↓
Research(反応を分析) → 次のContentに反映(PDCA)
```

秘書エージェントの動き方のルールは、sb-mac直下の`CLAUDE.md`にある。
