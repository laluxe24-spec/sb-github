# AI組織図

sb-macで動いてるAI(自動化の担当プロセス)を、部署とメンバーの形で整理したもの。りゅーじ君は個別のAIを意識せず、秘書AI(このセッション)を窓口にやり取りする。

## 共通の設計図(どのメンバーも必ずこの形)

新しいメンバーを追加する時は、必ずこの5段階に沿わせる。中身の分析方法(判断ロジック)は自由だが、この骨組みは崩さない。これが崩れるとメンバーごとにバラバラの形式になり、収拾がつかなくなる。

```
1. 新着チェック(前回からの差分だけを見る)
2. 目的にあった分析(メンバーごとに中身は違う)
3. 決まった形式で保存(見た目は読みやすい文章のまま)
4. 内部メタデータ更新(裏側の管理情報)
5. 処理済み記録(次回同じものを見ないように)
```

## 増やし方の方針

- **行動系のAI**: ソースが増えるだけなら増やさない(今のAIの対象フォルダに追加するだけ)。本格的に新しいジャンル(営業・マーケなど、恋愛以外)が増えたらジャンルごとに1人追加。
- **会話系のAI**: 新しい「人」の会話を分析し始めるたびに1人追加(人物像がブレないように、人ごとに専用)。
- **チェックAI**: 当面1人のまま。1日の変更量が多すぎて見きれなくなったら、分析AIと同じ単位(ジャンル別・人別)で分ける。
- どのメンバーも、上記の「共通の設計図」5段階には必ず沿わせる。

## ジャンル(置き場所)の自動判断について

**基本方針**: `03_Knowledge`内のどのジャンルフォルダに入れるかは、**内容を見て自動判断するのが標準**。TikTok=営業、X=恋愛、のように今は固定されて見える部分があるが、これは「今はたまたまそのジャンルのアカウントしか登録されてないから」であって、恒久的な縛りではない。

- りゅーじ君はどのリソース(TikTok・X・Instagram・Webなど)にも、将来いつでも別ジャンル(インテリアなど)のアカウント・情報源を追加したいと思っている
- なので、行動AI・会話AIなど各解析係は、**「このソースはこのジャンル専用」と決め打ちにせず、常に内容を見てジャンルフォルダを判断する作りにしておく**のが正しい設計
- 判断先のジャンルフォルダが既存に無ければ、新しく作ってよい(`99_Other`は最終手段、まず該当しそうな新ジャンルを作ることを優先する)

現状、行動AIの指示書(`knowledge_analyzer_action_prompt.md`)はX/TikTokの保存先を固定で書いてしまっているので、**次にこのファイルを触るタイミングで「内容を見て判断」方式に書き直す**(このAI組織図の方針とズレてる状態なので、直し忘れないようにここにメモしておく)。
