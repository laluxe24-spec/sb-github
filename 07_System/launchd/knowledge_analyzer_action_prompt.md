Xの投稿・TikTokの文字起こしを、そのまま知識として保存しません。必ず「分析→検証→条件付け」を通してから保存します。「Xで言われていた」は「正しい」ではありません。

## 全体の流れ

```
X投稿(7アカウント)・TikTok文字起こし
  → 解析(このプロンプトの役目、内容を見てジャンル判断も行う)
  → 確認AI(knowledge_reviewer_action_prompt.md、別プロセスで後追い実行)
  → 03_Knowledge/<該当ジャンル>/<情報源名>_行動テクニック.md へ保存
```

## 0. 新着の洗い出し

`07_System/launchd/knowledge_progress.json` の `processed_files` に載ってないものだけを対象にする。

- **X投稿**: `02_Sources/02_X/data/@<7アカウント>/posts.json`(kw1ew以外の7アカウント。中の各要素が1件、`id`で処理済み判定)
- **TikTok**: `02_Sources/03_TikTok/data/*/transcripts/*.md` → `03_Knowledge/04_Sales/` へ(こちらは単独アカウントなので複数アカウント横断ルールの対象外)

新着が無ければ何もせず終了してよい。

## 1. 処理の目的

1投稿を単独で知識化しない。複数の発信者(アカウント)を横断して比較し、共通するパターンだけをKnowledgeにする。

**0段階目: ジャンル分類**。「このアカウント/この情報源はこのジャンル専用」と決め打ちしない。投稿・文字起こしの内容そのものを見て、`03_Knowledge`内のどのジャンルフォルダ(`03_Romance`, `04_Sales`, `05_Marketing`, `06_Interior`など既存フォルダ)に該当するかをその都度判断する。該当するフォルダが無ければ新しく作ってよい(`99_Other`は最終手段)。同じ情報源(Xなど)でも、投稿によってジャンルが割れて構わない(例: 同じXの中に恋愛系アカウントとインテリア系アカウントが混在していたら、それぞれ別ジャンルとして処理する)。

1. 判定したジャンルごとに、同じテーマを扱っている投稿を、アカウントをまたいで集める(横断比較は同じジャンル内でのみ行う)
2. 次のいずれかに当てはまるものは「統合Knowledge」の候補にする
   - 複数アカウントで一致している
   - 表現は違うが本質が同じ
   - 条件は違うが共通する原則がある
   - 既存Knowledgeと一致している
3. 次のいずれかに当てはまるものは「参考情報・保留」にする(確定Knowledgeにしない)
   - 1アカウントだけの主張
   - 他の情報と大きく矛盾する
   - 条件が特殊すぎる
   - 情報量が少ない
4. 「事実を証明すること」が目的ではない。「複数の発信者から見ても共通しているパターンか」を確認する

単独アカウントで他と横断できない情報源(例: TikTokの`@eigyou.inui`)は、その投稿内でメカニズムの説明が筋通っているかどうかで判断してよい。

## 2. Knowledgeの完成形(見た目)

**見た目は読みやすい文章形式を維持する。カード型データベースにはしない。**

判定したジャンルフォルダ(`03_Knowledge/<ジャンル>/`)の中に、`<情報源名>_行動テクニック.md`(例: `X_行動テクニック.md`, `TikTok_行動テクニック.md`)として保存する。同じ情報源でもジャンルが違えば別ファイル(別フォルダ)になる。項目ごとに: タイトル / 共通している考え方 / 複数アカウントの共通点 / 統合した原則 / どういう状況で使うのか / 具体的な行動 / 例外・条件 / 関連Knowledge

個別アカウントの意見を並べるのではなく、共通部分を抽出して原則化する。根拠レベル(A〜D)は末尾に付ける。
- A: 心理学・行動科学の確立した理論に対応
- B: 複数の情報源で独立して繰り返し主張されている経験則
- C: 一つの情報源のみだが、メカニズムの説明が筋が通っている
- D: 根拠が弱い・個人差が大きい

出典アカウント名は書かず内容の妥当性だけで判断する。煽情的・操作的なテンプレ投稿(釣り文句集など)は対象から除外する。既存ファイルに項目があれば追記・更新、無ければ新規追加。

## 3. 内部管理情報(見た目には出さない)

`07_System/launchd/knowledge_meta.json` に、Knowledge項目ごとの内部情報を保存・更新する(既存ファイルがあるので、会話系担当のエントリを消さずに自分のエントリだけ追加・更新する)。

```json
{
  "<保存した項目タイトル>": {
    "type": "action",
    "genre": "保存先のジャンルフォルダ名(例: 03_Romance)",
    "file": "実際に保存したファイルパス(例: 03_Knowledge/03_Romance/X_行動テクニック.md)",
    "sources": ["元になった投稿id(複数可)、またはTikTokのtranscripts/<video_id>.md"],
    "matched_accounts": ["一致が確認できたアカウント名のリスト"],
    "confidence": "A〜D",
    "status": "verified" または "tentative" または "hold" または "conflict",
    "hold_reason": "holdの場合のみ、保留理由を一言",
    "related": ["関連する他のKnowledge項目タイトル"],
    "last_updated": "YYYY-MM-DD"
  }
}
```

保留(hold)にした項目は、本文の`.md`には書かず、この`knowledge_meta.json`にstatus:"hold"として記録するだけにする。

- Xの投稿は `<アカウント名>/<投稿id>`
- TikTokは `transcripts/<video_id>.md`
