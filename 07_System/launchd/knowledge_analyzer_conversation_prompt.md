## 1. 処理の目的

「正しいか」の検証ではなく、「なぜその返し・言い回しが面白い/効いているのか」を、りゅーじ君が別の場面でも再現できる形に分解すること。りゅーじ君が良いと思って保存対象に残っているスクショは、根拠が弱いという理由だけで却下しない。

**例外(必ず除外)**: 上記の「根拠が弱くても却下しない」方針とは関係なく、**性的な体験報告・行為の詳細描写を含むやり取り**は、会話の面白さやテンポが良くても対象から除外する(Knowledgeにもmeta.jsonにも起こさない、`processed_files`に記録だけして終わり)。

個別事例の「型」だけでなく、**似た状況でなくても「kw1ewならこう返しそう」と想像できるレベルの人物像**も合わせて育てる(2を参照)。

## 2. kw1ewの人物像・会話スタイル(総括)

`X_会話テクニック.md`の一番上に置く、事例が増えるたびに更新していく総括セクション。個別の「型」カードとは別に、次のような**キャラクター全体の傾向**をまとめる。

- ユーモアのセンス(どんなボケ・ツッコミが多いか、皮肉系か天然系かなど)
- 言葉選びの傾向(語彙・口調のクセ)
- 真面目になる場面とふざける場面の境界線
- 距離感の詰め方(初対面〜親しくなった後でどう変わるか)
- NG・やらないこと(下品すぎる、詮索しすぎる、など踏み込まない一線)

新しい事例を処理するたびに、この総括を「変わらない」「補強された」「新しい側面が見つかった」のどれかで更新する。矛盾する側面が見つかったら消さずに「〜な面もあれば、〜な面もある」と両方残す。

## 3. 個別の型への分解

各スクショについて、次の順で個別の型に分解する。

1. **元の返し**: スクショに写ってる実際のやり取り(誰が何と言ったか)
2. **何が面白いのか**: 具体的にどこがウケている/効いているのか
3. **会話構造**: 相手の発言 → この返し、という流れのどこで何をしているか
4. **心理・感情の動き**: 相手や場の空気がどう動いたか
5. **言葉の選び方**: 使われてる言葉・言い回しの特徴
6. **テンポ・距離感**: 間の取り方、フォーマル/カジュアルの度合い
7. **別の場面への応用**: 同じ構造を別の状況で使うなら何が変わるか
8. **自分で使うための型**: 「相手が(条件・状況)と言ってきたら、(この構造)で返す」という、IF-THEN形式の再現可能なルールとして書く。抽象的な説明で終わらせず、りゅーじ君が後で実際に似た場面に遭遇した時、AI(このプロジェクトの担当セッション)に「こう言われたんだけど、kwならどう返す?」と相談すれば、このルールを当てはめてその場で返しを一緒に考えられるレベルの具体性にする。

単なる「使えるフレーズ集」にはしない。フレーズではなく構造を残す。

## 4. Knowledgeの完成形(見た目)

`03_Knowledge/03_Romance/X_会話テクニック.md` に保存する。項目ごとに: タイトル / 元ネタ(スクショ番号+tweet_url) / この会話の面白さ / 会話構造 / なぜこの言い方が機能するのか / 再現するための分解 / 応用パターン / 使える場面 / 使わない方がいい場面 / 具体例 / 関連Knowledge
