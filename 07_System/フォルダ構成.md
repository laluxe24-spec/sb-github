# フォルダ構成

## 全体(sb-macの一番上の階層)

- 01_Company(会社): izunaなど、リアルな会社に関する情報
- 02_Sources(情報源): Kindle・X解析など、外部から集めた生の情報
- 03_Knowledge(知識): 情報源を整理・体系化した知識
- 04_MyKnowledge(自分の知識): 自分の考察・気づき・仮説
- 05_Projects(プロジェクト): SNS運用・noteなど、発信していく活動(作業中のものはここ)
- 06_Outputs(成果物): 公開・提出済みの完成物(05から完了したら移動)
- 07_System(運用基盤): 運用ルール・ツール設定など

## 各プロジェクト(02_Sources配下など)の中の構成

1つのプロジェクトフォルダ(例: 02_Sources/01_Kindle)の中は、基本この3種類で揃える。

- `docs`(説明書類)だけは全プロジェクト必須。残り2つ(`scripts`/`data`)は、そのプロジェクトの内容に応じて必要な時だけ作ればいい。
- **02_Sources配下には`knowledge`フォルダは作らない**。まとめた知識は最初から03_Knowledge(ジャンル別)に直接書く。02_Sourcesは「集めた生データを置く場所」専用にする。

### docs
「documents(説明書類)」の略。プロジェクトの説明を置く場所。

- `README.md`(概要)と`操作メモ.md`(詳しい手順)の2つを置く
- どのプロジェクトにも必ず作る、必須のフォルダ

**README.md**: プロジェクトの概要(何をするものか)を短くまとめたファイル。詳しいやり方は書かず、あくまで入り口の説明だけ。

**操作メモ.md**: Claudeが作業を再現するための、詳しい手順書。どんな指示が来たら動くか(トリガー)、実際の手順、過去にハマった注意点がまとまってる。

### scripts
「script(台本・脚本)」の複数形。自動で実行するプログラムのファイルを置く場所。

- 必要な時だけ作る
- 中身(`.py`や`.js`)を消すと、その自動化ができなくなるので注意
- 操作メモ.mdが「人が読む手順書」なのに対して、scriptsは「機械がそのまま実行するプログラム本体」という違いがある

### data
収集した生データ(画像・取得ファイルなど)そのものを入れる置き場。

- 「やったこと」の記録ではなく、実際に集めた実物のファイルが入る
- 必要な時だけ作る
- knowledgeに分析結果をまとめた後も、後で検証・再分析できるように消さずに残しておく
