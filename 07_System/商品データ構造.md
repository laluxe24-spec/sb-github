# 商品データの構造(Research/Interior共通)

Research(商品検索)が集めて、Interior(部屋づくり)が使うデータの型。この形式を崩さないことで、どっちのAgentも迷わず連携できる。

```json
{
  "name": "商品名(検索サイトに表示されてる正式名称)",
  "category": "ベッド/デスク/照明/収納/ラグ/ソファ/TV台/その他 など",
  "price": 12800,
  "size": {
    "width_cm": 100,
    "depth_cm": 50,
    "height_cm": 40
  },
  "color": "ホワイト",
  "material": "スチール",
  "shop": "楽天市場" または "Yahoo!ショッピング" など,
  "product_url": "実際の商品ページURL",
  "image_url": "商品画像URL",
  "note": "在庫状況・配送目安など補足があれば",
  "fetched_at": "YYYY-MM-DD"
}
```

**注意点**
- `product_url`・`image_url`は、必ず実在するページから取得した本物のURL(架空のURLを作らない)
- サイズが商品ページに無ければ、`size`は`null`のままにする(勝手に推測しない)
- 将来アフィリエイト経由の商品が増えたら、`shop`に発行元を追記し、`affiliate_url`フィールドを追加できるようにしておく(今は未使用)

## Interior企画1件の保存形式

`05_Projects/interior/<企画名>/project.json` に、条件・選んだ商品リスト(上記の形式の配列)・合計金額・レイアウトの説明・画像生成用の差し込みデータ(下記)をまとめて保存する。

```json
{
  "conditions": { "room_size": "8畳", "budget": 100000, "concept": "モダン・モノトーン", "purpose": "男性一人暮らし" },
  "furniture": [ /* 商品データの配列(上記の形式) */ ],
  "total_price": 98000,
  "layout_note": "ベッドを窓側に配置し、デスクは入口側の壁沿いに...(具体的な配置の説明)",
  "image_generation_request": {
    "status": "not_yet_connected",
    "room_dimensions": { "width_cm": 350, "depth_cm": 270 },
    "style_keywords": ["モダン", "モノトーン", "ホテルライク"],
    "furniture_refs": ["家具データのimage_urlを並べたもの"],
    "note": "画像生成サービス(Higgsfield等)をMCP接続後、このデータをそのまま渡せる形にしてある"
  }
}
```
