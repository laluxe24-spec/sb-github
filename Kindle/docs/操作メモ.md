# 操作メモ(Kindle本のスクショ取り込み・重複整理の再現手順)

このメモは、Claude自身が次回以降のセッションでも同じ作業を再現できるようにするための手順書。
複数の本を扱う前提のフォルダ構成になっている。

## フォルダ構成
```
Kindle/
├── docs/                       共通ドキュメント(このファイル)
├── scripts/
│   ├── kindle_screenshot.py     共通のキャプチャスクリプト(全ての本で使い回す)
│   └── venv/                    スクリプト実行用のPython仮想環境
├── data/
│   └── <本のタイトル>/
│       └── screenshots/          その本のページ画像(0001.png, 0002.png, ...)
└── knowledge/                   本の内容から生成した要約・分析結果を置く場所
```
新しい本を取り込む場合は `data/<本のタイトル>/` が自動的に作られる(手順1参照)。

## トリガー
ユーザーが「この本を読み込んで」「この本をスクショして」のように指示したら、以下の手順を自動的に(逐一やり方を聞かずに)実行する。

## 手順1: キャプチャ

Kindleアプリで対象の本を開いた状態で実行する。

```
cd Kindle/scripts
./venv/bin/python3 kindle_screenshot.py <本のタイトル>
```

- 第1引数(本のタイトル): 省略すると `untitled` フォルダになるので、複数の本を扱うときは必ず指定する。
- 第2引数(ページ数上限、省略可): 通常は指定不要。デフォルトで5000ページ分の上限があるが、これは「本当に何かおかしくなった時の安全装置」に過ぎず、実際にはページが変化しなくなった時点(=最終ページ)で自動停止する。5000ページを超えるような本は現実的にまず無いので、通常は本のタイトルだけ渡せばよい。
- 出力先は自動的に `Kindle/data/<本のタイトル>/screenshots/` になり、同じフォルダに `capture.log`(実行ログ)も自動生成される。

**最終ページ自動停止(2026-09-14実装)**: ページ送り後に2回連続で画面が変化しない場合、最終ページに到達したとみなしてループを打ち切り、重複した最後の1枚も自動削除する。ページ数上限を指定する必要がないため、「本のページ数を事前に知らないと何回指定すればいいか分からない」「上限を低く指定すると最後まで撮り切れない」「上限を大きくしすぎると最終ページで無駄な重複が大量発生する」といった問題がすべて解消されている。万一、上限ページ数に到達しても最終ページを検出できなかった場合は、`capture.log`に警告が出るので、その場合だけページ数上限を増やして再実行する。

なお、縦書きの本では最初「右矢印キーではページが変わらない」ことがある(そのページが本のレイアウト上、右方向には送れない場合など)。その場合スクリプトは自動で左矢印キーに切り替えて続行する。

キャプチャ後は `capture.log` を一度確認し、「右矢印キーではページが変わりませんでした」のような記録がないか見ておく(途中でキーが効かなくなった痕跡がないかの確認)。

## 手順2: 重複画像の削除(2段階)

`data/<本のタイトル>/screenshots/` フォルダ内の重複を、以下の2段階で検出・削除する。**削除はユーザーに逐一確認を取らずに自動で行ってよい**。ただし何を(何枚)削除したかは結果として簡潔に報告する。

### 2-1. MD5完全一致での削除
全画像のMD5ハッシュを計算し、完全に同一のバイト列を持つファイルをグループ化する。Kindleウィンドウがフリーズした/フォーカスを失った/最終ページで同じ画面が繰り返し撮影された、といったケースで発生する完全一致の重複を検出する。各グループの最初の1枚だけ残して残りを削除する。

### 2-2. 知覚的ハッシュ(dHash)での近似重複の削除
MD5だけでは、同じページでもウィンドウサイズが異なる撮影(ピクセルは微妙に違うが内容は同じ)による重複を見逃す。`venv`にインストール済みのPillowを使い、各画像をグレースケール化・縮小してdHash(差分ハッシュ)を計算し、ハミング距離が近い画像同士をペア/クラスタとして検出する。

**重要な落とし穴**: dHashは「章の扉ページ」(例:「第一夜」「第二夜」のような、白背景に短い数文字だけが同じ位置に配置されたページ)に対して誤検出を頻発する。実際の文字内容が違っても、大まかなレイアウト(余白と文字ブロックの位置)がほぼ同じため、ハミング距離が0〜2という極めて近い値になってしまう。過去に、全く異なる5つの章(第一夜〜第五夜)やあとがきページが「同じ重複グループ」として誤って一つにまとめられたことがあった。

そのため、**dHashで検出した候補は必ずReadツールで画像を実際に開いて目視確認してから削除すること**。特に以下のページタイプは要注意:
- タイトルページ、章扉ページ(短文+大量の余白)
- 本文が少ないページ全般

本文がぎっしり詰まった通常のページ同士であれば、dHashの距離0はほぼ確実に本当の重複(同一ページの再撮影)と判断してよい。

## 手順3: 後片付け

重複整理が完了したら、`capture.log` は用済みなので削除する。診断用の一時ファイルであり、整理作業が終わった後は残しておく必要がない。
